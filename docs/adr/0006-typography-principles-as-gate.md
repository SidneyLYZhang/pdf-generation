# 排版原则从散文升级为构建门禁：阈值进代码，偏离进 `doc.yml`

`docs/总排版原则.md` 与 `docs/细节排版原则.md` 原本是两份未入库的长文：不在安装契约里（`INSTALL.md` 的目录树只列 `references/*.md`），运行时不读，也没有任何机制保证产物符合它们。实测当前默认值就违反多条——七种 Kind 行距实测 1.379×（低于 1.4 的下限），`note` 段距比行距还紧，`book` / `textbook` / `novel` 同时开首行缩进与段距，`letter` 标题只有正文的 1.22 倍，英文文档每行 88–110 字符（区间 50–75）。而「文档写了就会遵守」这条路已被证伪：`references/style-knobs.md` 与生成器只差一次重跑，就漂了一行。决定：把规范蒸馏成 `references/typography.md`，作为随技能分发的唯一规范源；两份原文入库，只作出处与论证。强制力分两档——结构性矛盾（缩进与段距并存、无缩进时段距不大于行距）直接 `SpecError` 阻断；区间越界（行距、每行字数、标题字号比）只警告，但警告必须写进该文档的排版方案，不许静默。优先级定为「机构/期刊规范 > 原则 > 用户明确要求 > Kind 默认」，出口只有两个：用户显式授权、机构规范，两者都要记进 `doc.yml` 的偏离记录（带 `source`）；一次性命令行只做写入入口，不在内存里放行——偏离是文档属性，放内存里会让同一份 Markdown 时而能构建、时而不能。阈值以代码里的常量表为单一事实源，规范文档的数值表由 `gen_style_docs.py` 生成，加 `--check` 模式，并在 unittest 里比对，一条测试同时看住两份文档。

原则文档自身有歧义的地方，口径一并钉死：行距倍数按「基线距 ÷ 字号」算，`1 + leading` 会算出 1.65× 的假象，实测只有 1.379×；「标题 ≥1.3 倍」只约束一级标题，二三级靠字体族与字重分层；字体按用途计数（正文中文、正文西文、等宽），标题族不计入但全篇唯一；小说保留两端对齐——实测汉字 advance 恒为 1.000em，Typst 用整字断行而非拉伸字距，禁忌针对的成因不成立；教材正文保持宋体，对照表那一格「技术教材：黑体」降级为场景默认；英文正文类文档（`report` / `article`）的版心按原则收窄到 4.8cm（约 70–75 字符）；信函与便签属于短文本，按「一次读完」处理，不放宽页边距，中文文档不受影响。

## Considered Options

- **纯文档驱动**：把原则并入 `SKILL.md`、靠完成判据约束，不动代码。最省事，但等于承认「违反也没有后果」，而现有默认值本身就是反例。
- **所有越界一律阻断**：字面最符合「任何情况下都满足」，但每行字数是估值（同一份 spec 换 A5 就超），拿估值阻断构建是把工具变成障碍。
- **阈值写在 Markdown、脚本每次解析**：单一事实源确实只剩一处，但解析散文表格比生成一张表脆弱得多，且格式一改就静默失效。
- **用户明确要求优先于原则**：交互最顺，但「任何情况都满足原则」这句话随之作废，且用户会以为工具在敷衍。
- **一次性命令行开关放行偏离**：实现最便宜，但重跑即失效，故障表现为「同一份文档有时能构建、有时不能」。

## Consequences

- 出现新的失败模式：构建可能以退出码 1 拒绝，错误信息必须直接给出「改哪个旋钮、改到多少」，否则用户只会觉得工具坏了。
- 用户明确要求可能被拒，这是本决策最反直觉的一条，`SKILL.md` 必须写明优先级与出口，否则会被当成 bug 上报。
- 行距上调让中文样张约 +7% 页数，英文版心收窄让英文样张约 +15%；`examples/*.pdf` 全部要重建，与历史提交不再可比。
- 行距倍数依赖字体度量常数（Noto Serif SC 在 11pt 下实测行盒 8.00pt ≈ 0.727em，Libertinus 0.658em）。换字体栈后常数失效，所以这一项只能警告、不能阻断；常数值写进规范并由测试钉住。
- 门禁挂在 `resolve_style` 之后，`build` / `style` 两个入口天然覆盖；`build x.typ` 是直通分支，看不到 spec，需在 `cmd_build` 入口另加一处，否则留了一条绕过路径。
- 两份原文入库后与规范文档存在再次分叉的风险，靠「出处 / 规范」的显式声明加 `--check` 守住；若最终仍分叉，删掉原文只留规范是允许的回退。
- 日后若要放宽，最省事的回退是砍掉阻断档、只留警告，而不是退回纯文档驱动——那样等于回到今天这个状态。
